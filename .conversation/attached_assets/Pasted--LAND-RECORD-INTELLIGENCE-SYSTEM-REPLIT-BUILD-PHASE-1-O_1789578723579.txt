# LAND RECORD INTELLIGENCE SYSTEM

## REPLIT BUILD — PHASE 1 ONLY

You are building a production-style hackathon MVP called:

**LAND RECORD INTELLIGENCE SYSTEM**

This is an AI-powered land-record document intelligence and verification application.

IMPORTANT: **DO NOT BUILD THE ENTIRE PRODUCT IN THIS PROMPT.**

This is **PHASE 1 ONLY**.

Your goal is to create a clean, working foundation that later phases can extend without rewriting the architecture.

---

# 1. CORE PRODUCT IDEA

The final application will eventually support this workflow:

DOCUMENT UPLOAD
→ AI DOCUMENT UNDERSTANDING
→ STRUCTURED EXTRACTION
→ FIELD VALIDATION
→ CROSS-DOCUMENT RECONCILIATION
→ EXISTING RECORD COMPARISON
→ CONFLICT DETECTION
→ INTEGRITY SCORE
→ HUMAN OFFICER REVIEW
→ FINAL VERIFIED RECORD
→ AUDIT TRAIL

For this phase, implement only the foundation.

Do NOT implement AI processing yet.

Do NOT implement OCR yet.

Do NOT implement reconciliation yet.

Do NOT implement the verification score yet.

Do NOT implement the document scanner animation yet.

---

# 2. TECH STACK

Use a simple architecture that is cheap to run and easy to extend on Replit.

## Frontend

* React
* TypeScript
* Vite
* Tailwind CSS
* shadcn/ui where useful
* Lucide React icons
* React Router
* TanStack Query

## Backend

Use Node.js + TypeScript.

Prefer:

* Express
* PostgreSQL
* Prisma ORM

Use REST APIs.

Do NOT create microservices.

Do NOT create a separate Python backend.

Do NOT create FastAPI.

Do NOT use Kubernetes.

Do NOT create a separate AI server.

The application should be a **single modular full-stack application**.

# 11. FILE STORAGE

Do not store document binary data directly inside PostgreSQL.

Use file storage supported by the Replit environment.

Create an abstraction such as:

StorageService

with methods:

* uploadFile()
* getFile()
* deleteFile()

The application should be structured so storage can later be replaced by S3-compatible storage without changing business logic.

Never expose private storage credentials to the frontend.
